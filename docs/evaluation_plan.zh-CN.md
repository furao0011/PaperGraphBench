# PaperGraph-Bench 测评方案：指标 1.3 多维度幻觉评估指标体系

本方案面向测试人员，使用公开数据集评估模型的科学论文理解与幻觉行为，给出环境配置、运行步骤、结果指标和验收方式。

> **快速使用：准备好评判模型和被测模型的 API Key、Base URL 与模型名称后，在仓库根目录运行 `.\start.ps1`；macOS/Linux 运行 `bash ./start.sh`。程序自动评测已有的 12 篇论文并统计结果。**

## 一 方法原理与测评目标

PaperGraph-Bench 将论文组织为包含研究阶段、知识要点、推理关系和图文证据的论文图谱。知识要点对应可以核对的论文事实或主张，推理关系连接方法、实验与结论，图表为相关要点提供多模态证据。

基于论文图谱，系统生成覆盖性问题、误导挑战问题和关联推理问题，并开展连续多轮问答。评判模型结合论文证据判断回答的覆盖情况与错误类型；遇到遗漏或幻觉时，系统继续追问，观察被测模型能否补全信息、纠正错误。

这一过程同时考察“读到了多少”“是否受误导”“产生了什么幻觉”以及“能否修复错误”，体现模型在完整论文阅读过程中的表现。本方案对应**指标 1.3「多维度幻觉评估指标体系」**，重点测试以下四个维度。

| 评估维度 | 测试内容 | 主要结果及含义 |
| --- | --- | --- |
| 知识覆盖 | 通过宏观问题检查模型对论文各研究阶段与关键知识的理解 | 首答知识覆盖率、宏阶段完成率，越高表示理解越充分 |
| 挑战诱发幻觉 | 在问题中引入错误前提、过强结论或错误关系，观察模型是否接受误导 | 总体、文本和多模态挑战幻觉率，越低表示抵抗误导的能力越强 |
| 幻觉行为 | 记录对话中出现的幻觉，分析其数量与类型 | 每篇平均幻觉事件数、含幻觉轮次比例及四类分布，反映幻觉的频度和性质 |
| 错误修复 | 针对信息遗漏与幻觉分别跟进提问，观察补全和纠错过程 | 两类修复的成功率与平均尝试轮数，反映模型的补全和纠错能力 |

结果采用论文中的指标口径：覆盖指标考察宏观问题的首次回答，挑战幻觉率表示接受误导的挑战占比；修复成功率依据实际跟进任务计算，平均轮数统计完成或结束前的尝试次数。修复能力应结合成功率与轮数综合比较。

### 四类细粒度幻觉

| 幻觉类别 | 含义 | 测试观察 |
| --- | --- | --- |
| KC 证据冲突 | 回答中的事实或主张与论文知识要点及其证据冲突 | 检查模型是否准确理解论文事实 |
| 错误前提接受 | 接受与论文证据不符的问题前提，并据此作答 | 检查模型能否识别并纠正错误前提 |
| 过度推断接受 | 接受超出实验范围、适用条件或结论强度的说法 | 检查模型能否把握论文结论的边界 |
| 错误关系接受 | 接受论文知识要点之间缺乏依据或被颠倒的关系 | 检查模型能否理解方法、证据与结论之间的联系 |

评测结束后，程序自动输出各模型的分类数量，并保留相应问题、回答与评判记录，便于结合论文证据查看具体实例。

## 二 环境与 API 配置

### 2.1 获取代码与数据

准备 Python 3.11+ 和 [uv](https://docs.astral.sh/uv/)，完整克隆公开仓库：

```powershell
git clone https://github.com/furao0011/PaperGraphBench.git
cd PaperGraphBench
```

仓库包含 12 篇论文的数据包及配套图片。启动脚本自动准备项目依赖。使用模型服务 API 时，本地承担数据读取、调度和统计，可在普通计算机上运行；模型推理资源由 API 服务提供方承担。

### 2.2 运行前必填

> **测试人员需要自行提供以下两组 API 配置，填写在仓库根目录的 `config.env` 中。首次执行启动脚本会生成该文件并提示待填项；填写完成后再次执行相同命令。调用费用由所使用的模型服务计费。**

| 服务角色 | API Key | Base URL | 模型名称 | 能力要求 |
| --- | --- | --- | --- | --- |
| 评判模型 | `API_KEY` | `BASE_URL` | `LLM_MODEL` | OpenAI-compatible 对话接口，支持 JSON 输出 |
| 被测模型 | `EVAL_TARGET_API_KEY` | `EVAL_TARGET_BASE_URL` | `EVAL_TARGET_MODEL` | OpenAI-compatible 对话接口，支持文本和图片输入 |

Base URL 使用服务商提供的 API 根地址，例如 `https://api.example.com/v1`；程序会自动补全请求端点。模型名称填写账号下实际可调用的模型 ID。两种角色可以使用同一服务，各自的配置项均需填写。

其余配置保留默认值即可。默认评测已有数据集需要上表两组服务；详细配置见 [API 配置说明](configuration.md)。配置文件及密钥由测试人员自行保管。

## 三 测试步骤

### 3.1 先测试单篇论文

填好 API 后，在仓库根目录执行：

```powershell
.\start.ps1 --paper-id ConVis
```

macOS/Linux 将 `.\start.ps1` 替换为 `bash ./start.sh`。确认单篇评测完成、结果文件正常生成后，再开展全量测试。

### 3.2 全量评测与自动统计

```powershell
# 评测全部 12 篇论文，并自动统计结果
.\start.ps1

# 可选：同时评测两篇论文，独立重复三轮
.\start.ps1 --workers 2 --repeats 3
```

macOS/Linux：

```bash
bash ./start.sh
```

默认每模型评测一轮。比较多个模型时，可使用 `.\start.ps1 --models model-a model-b --workers 2`，将名称替换为实际可用的模型 ID，并为各模型配置相应服务。跨模型比较使用相同题包、评判模型和运行设置。

程序在终端展示进度，并打印本批次的结果目录；运行日志保存在批次的 `main.log` 中。Windows 若提示脚本执行受限，可使用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1` 启动。

### 3.3 对已有评测结果重新统计

仓库发布的历史结果可以直接离线统计：

```powershell
uv run --locked python scripts/summarize_results.py --result-root eval_result
```

结果保存在 `eval_result/statistics/`。将命令中的路径替换为其他评测批次目录，即可重新生成该批次统计。此步骤使用已保存的报告和对话记录，无需模型服务。

## 四 查看结果

新模型测试结果位于 `outputs/testing/<批次>/`，具体位置以程序打印的路径为准。建议按以下顺序查看：

| 文件 | 用途 |
| --- | --- |
| `statistics/four_dimensions.csv` | 查看各模型的四维评估结果 |
| `statistics/failure_category_by_model.csv` | 查看四类细粒度幻觉的数量与分布 |
| `statistics/summary.csv` | 查看完整模型指标汇总 |
| `statistics/per_paper.csv` | 查看各篇论文、各轮评测的结果与完成情况 |
| `main.log` | 查看运行进度及异常信息 |

需要进一步分析时，可查看批次内各论文的评测报告和完整对话，了解具体问题、模型回答、错误原因及后续修复过程。统计表中的 N/A 表示本次未触发相应测试情形，可通过增加独立轮次或补充模型完善覆盖。

## 五 验收方式与交付材料

本项验收关注评测工具能否完成测试并提供四维指标与细粒度分析；模型得分用于展示被测模型的能力。

| 验收内容 | 检查方式 |
| --- | --- |
| 测试可运行 | 按步骤完成单篇及全量评测，所选论文与模型均有完成记录，日志可查 |
| 四维结果齐全 | 查看四维结果表，确认知识覆盖、挑战诱发幻觉、幻觉行为和错误修复均有输出，并检查实际测试覆盖情况 |
| 细粒度分类可用 | 查看四类幻觉统计，结合实际发生的事件检查类别、错误原因及论文证据 |
| 修复过程可查看 | 选取遗漏补全和幻觉纠错实例，查看跟进提问、模型回答与修复结果 |
| 结果可复核 | 对同一批次运行离线统计，核对汇总指标与分类结果一致 |

交付代码版本、环境与模型说明、本批次结果表、评测报告、对话记录及日志。对于本次尚未触发的类别或修复情形，在测试报告中说明，并通过追加独立测试补充实例。
