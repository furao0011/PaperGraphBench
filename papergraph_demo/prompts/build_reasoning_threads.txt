Task:
Build cross-turn reasoning threads from the Macro Spine, Active KCs, verified active edges, verified active paths, and edge coverage diagnostics.

Rules:
1) Each thread must span at least two Macros.
2) Each thread must use only active KC IDs, Macro IDs, and verified edge IDs from the input.
3) Each thread must contain 3-4 planned turns.
4) A thread is not a single multi-hop question. It must establish earlier premise/evidence and later ask for a bridge.
5) Include one bridge_reasoning step with required_lit_kc_ids and supporting_edge_ids.
6) Include one review_consistency step with trigger_condition.at_review_stage = true.
7) Use only these thread_type values:
   - problem_to_method
   - method_to_result
   - module_to_ablation
   - claim_to_limitation
8) Use only these planned turn roles:
   - establish_premise
   - establish_evidence
   - bridge_reasoning
   - review_consistency
9) Thread IDs must be consecutive: RT1, RT2, ...
10) Step IDs must be consecutive inside each thread: RT1_STEP1, RT1_STEP2, ...
11) Every planned turn must include supporting_edge_ids. It may be empty except for bridge_reasoning.
12) Every planned turn must include expected_reasoning.
13) Prefer verified_active_paths when they exist, but you may build a thread from verified_active_edges directly.
14) Use edge_coverage_report to avoid overusing already well-covered areas when there are viable alternatives.
15) Do not expose KC IDs in question_goal wording; question_goal may reference the kind of claim conceptually.
16) Use English in all generated fields.
17) Return strict JSON only.
